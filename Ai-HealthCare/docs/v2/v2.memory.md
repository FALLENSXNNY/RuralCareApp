# 6. AI Language Decision

The application's selected language is the authoritative language for AI responses.

This rule applies to:

* General AI
* Pregnancy AI
* Emergency AI
* Future AI features

Required mapping:

```text
en → English response
hi → Hindi response
bn → Bengali response
```

The language of the user's input does not override the selected application language by default.

Example:

```text
Selected language: Hindi
User writes in English
        ↓
AI responds in Hindi
```

---

# 7. AI Language Persistence

The current locale must be passed to the AI layer on every request.

Do not depend on the AI remembering the language from a previous message.

Conceptually:

```text
Every AI request
      ↓
Read current locale
      ↓
Send locale/language context
      ↓
Generate response in that language
```

If the user changes the application language, the next AI response must use the new language.

---

# 8. AI Conversation Continuity

Changing the selected application language must not unnecessarily delete or reset the existing conversation.

Example:

```text
Conversation in English
        ↓
User switches to Hindi
        ↓
Existing conversation remains
        ↓
New AI responses are in Hindi
```

The implementation must preserve relevant conversation context where the existing V1 architecture supports conversation history.

---

# 9. AI Medical Safety

The AI is a healthcare-support system.

It must not:

* Claim to be a doctor
* Claim certainty about a diagnosis
* Pretend to examine the patient
* Invent medical facts
* Invent healthcare facilities
* Provide false reassurance
* Delay emergency care unnecessarily

The AI should clearly communicate uncertainty where appropriate.

---

# 10. Emergency Principle

Emergency handling must be prioritized over normal conversational behavior.

When a potentially serious situation is identified:

```text
Emergency concern
        ↓
Clear immediate guidance
        ↓
Recommend appropriate medical care
        ↓
Healthcare Finder
        ↓
Nearby facility
        ↓
Call / Directions
```

Do not bury urgent recommendations under long AI responses.

---

# 11. Emergency Independence from AI

Critical emergency functionality must not depend entirely on AI availability.

The following must remain possible even if AI fails:

```text
Emergency information
        ↓
Healthcare Finder
        ↓
Nearby healthcare
```

AI is an enhancement, not the single point of failure.

# 15. GPS Principle

GPS exists primarily to help patients locate healthcare.

It is not intended for continuous patient tracking.

Basic Healthcare Finder functionality should use location when required and should not require unnecessary background GPS tracking.

# 16. Location Permission Principle

Do not request location permission unnecessarily.

Request location when the user attempts to use a location-dependent feature.

The system must distinguish between:

```text
Permission denied
```

and:

```text

```

These are different failure states and should have different user guidance.

# 38. Current State & Critical UI/Localization Memory

```text
Recorded: 2026-09-02
Scope: Multilingual Foundation & UI Layout Resilience Hardening
```

### 1. UI Layout & Text Scaling Constraints
* **Devanagari (Hindi) & Bengali text scaling**: Non-Latin scripts naturally occupy greater horizontal width due to conjuncts and descriptive healthcare terms.
* **RenderFlex Overflow Rule**:
  - Any `Row` containing text labels and icons (e.g. emergency banners, action cards, hub cards) **MUST** wrap the text `Column` in `Expanded` or `Flexible`.
  - Main titles/labels **MUST** be wrapped in `FittedBox(fit: BoxFit.scaleDown, alignment: Alignment.centerLeft)` with `maxLines: 1`.
  - Subtitles **MUST** specify `maxLines: 1` and `overflow: TextOverflow.ellipsis`.
* **Resolved layout overflows**:
  - Top Red Emergency Banner in Hindi (`आपातकालीन सहायता (108)`) in `lib/core/widgets/emergency_button.dart`.
  - Emergency Landing Call 108 card in Bengali (`সারা ভারত অ্যাম্বুলেন্স পরিষেবা · ১০৮`) in `lib/features/emergency/screens/emergency_landing_screen.dart` and `offline_emergency_screen.dart`.

### 2. Bottom Navigation Bar Width & Label Rules
* In Material 3 `NavigationBar` with 5 destinations, each destination has ~70–75dp of width on mobile displays.
* Multi-line labels cause vertical baseline distortion.
* **Standardized 1-Word Navigation Labels & Order**:
  - English: `Home` (`/home`), `Pregnancy` (`/pregnancy`), `Care` (`/find-care`), `Records` (`/records`), `AI Health` (`/ai-chat`)
  - Hindi: `होम`, `मातृ देखभाल`, `अस्पताल`, `रिकॉर्ड्स`, `AI स्वास्थ्य`
  - Bengali: `হোম`, `মাতৃ যত্ন`, `হাসপাতাল`, `রেকর্ড`, `এআই স্বাস্থ্য`

### 3. Localization Coverage State

* **Pregnancy & Maternal Care**: `PregnancyDashboardScreen`, `PregnancySetupModal`, `AntenatalScheduleScreen`, and `PregnancyWarningSignsScreen` are fully localized in `en`, `hi`, `bn`.

* **Permissions & Lifecycle**:
  - Enum: `LocationPermissionStatus` (`granted`, `denied`, `permanentlyDenied`, `serviceDisabled`, `unknown`).
  - Timeout protection: 8-second timeout on device position requests with fallback to last-known position or rural district defaults to prevent UI hangs.

* **Haversine Distance**:
  - Exact spherical trigonometric distance calculation in Kilometers (`calculateDistanceKm`).
  - Smart distance formatting: returns meters (`< 1 km`, e.g. `850 m`) and kilometers (`>= 1 km`, e.g. `12.0 km`).

  - Dynamic live distance computation on all facilities when `UserLocation` is available.

  - Emergency scoring algorithm prioritizing 24x7 trauma hospitals and open facilities at the top of results during emergency triage.

* **Root Problem**: The Google Maps widget was embedded inside a scrollable column and draggable bottom sheet. Flutter's gesture arena gave priority to vertical drag gestures of the parent scroll view, causing map pan, pinch-to-zoom, and two-finger tilt to be captured or ignored.
* **Resolution**:
  - Attached an explicit `EagerGestureRecognizer` to the `GoogleMap` widget gesture recognizers set (`Factory<EagerGestureRecognizer>(() => EagerGestureRecognizer())`).
  - Enabled all native gesture flags: `zoomGesturesEnabled: true`, `scrollGesturesEnabled: true`, `tiltGesturesEnabled: true`, `rotateGesturesEnabled: true`, and `zoomControlsEnabled: false`.
  - Result: Smooth multi-touch zooming, panning, and rotating directly on the map without interfering with the bottom sheet sliding.
